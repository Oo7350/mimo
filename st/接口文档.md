# Mimo API 接口文档

## 基础信息

- **Base URL**: `http://localhost:8080`
- **认证方式**: JWT Bearer Token（请求头 `Authorization: Bearer <token>`）
- **响应格式**: 统一包装 `Result<T>`

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

- **Swagger 文档**: `http://localhost:8080/swagger-ui.html`

---

## 认证说明

### 公开接口（无需 Token）
- `POST /api/auth/login`
- `POST /api/auth/register`
- Swagger 相关路径

### 需要认证的接口
其余所有接口需在请求头携带：
```
Authorization: Bearer <token>
```

Token 有效期 24 小时，过期需重新登录。

### 角色权限

| 角色 | 说明 |
|------|------|
| `ROLE_ADMIN` | 团队/项目管理员 |
| `ROLE_MEMBER` | 普通成员 |

需管理员权限的操作：
- 邀请成员加入团队
- 移除团队成员

## 全局错误码

| 错误码 | 含义 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 冲突 |
| 500 | 服务器内部错误 |
| 1001 | 用户名已存在 |
| 1002 | 邮箱已存在 |
| 1003 | 用户不存在 |
| 1004 | 密码错误 |
| 1005 | Token 过期 |
| 1006 | Token 无效 |
| 1101 | 团队不存在 |
| 1102 | 团队名已存在 |
| 1103 | 已在团队中 |
| 1104 | 无权操作团队 |
| 1201 | 项目不存在 |
| 1202 | 项目名已存在 |
| 1301 | 列下仍有任务 |
| 1302 | 列不存在 |
| 1401 | Sprint 不存在 |
| 1402 | 已有活跃 Sprint |

## 一、认证模块

### 1.1 用户注册

```
POST /api/auth/register
```

**请求体：**
```json
{
  "username": "string (3-50字符)",
  "password": "string (最少6字符)",
  "confirmPassword": "string",
  "email": "string (邮箱格式)"
}
```

**响应：**
```json
{
  "code": 200,
  "message": "注册成功"
}
```

---

### 1.2 用户登录

```
POST /api/auth/login
```

**请求体：**

```json
  "password": "string"

```

```json
{
  "code": 200,
```

## 四、团队模块

```
POST /api/teams
```

```json

  "name": "string (必填)",
  "description": "string (可选)"
```

### 4.2 我的团队列表

```
GET /api/teams/my
```

```json
  "code": 200,
```

```
GET /api/teams/{id}
```

### 4.4 团队成员列表

```
GET /api/teams/{id}/members
```

**响应：**
```json
{
  "code": 200,
  "data": [
```

### 5.1 创建项目

```
POST /api/projects
```

**请求体：**
```json
{
  "name": "string (必填)",
```

## 七、任务模块

### 7.1 创建任务

```
POST /api/issues
```

**请求体：**
```json
{
  "projectId": 1,
  "columnId": 1,
  "title": "string (必填)",
  "description": "string (可选)",
  "type": "STORY | TASK | BUG",
  "priority": "HIGHEST | HIGH | MEDIUM | LOW | LOWEST",
  "assigneeId": 2,
  "sprintId": 1,
  "storyPoints": 5,
  "dueDate": "2024-02-01",
  "labels": ["前端", "核心功能"]
}
```

**Bug 类型额外字段：**
```json
{
  "severity": "BLOCKER | CRITICAL | MAJOR | MINOR | TRIVIAL",
  "stepsToRepro": "复现步骤描述..."
}
```

任务会自动生成 issueKey（如 `MIMO-1`），初始状态为 `TODO`。

### 7.2 获取任务详情

```
GET /api/issues/{id}
```

### 7.3 更新任务

```
PUT /api/issues
```

请求体同创建，需包含 `id` 字段。可修改的字段包括：title、description、type、priority、assigneeId、sprintId、dueDate、storyPoints、severity、stepsToRepro、status。

### 7.4 删除任务

```
DELETE /api/issues/{id}
```

软删除，同时删除关联的标签。

### 7.5 查询任务

```
POST /api/issues/query
```

**请求体：**
```json
{
  "page": 1,
  "size": 20,
  "projectId": 1,
  "sprintId": 1,
  "assigneeId": 2,
  "type": "STORY",
  "priority": "HIGH",
  "status": "TODO",
  "keyword": "登录"
}
```

所有筛选字段均可选。keyword 匹配标题和 issueKey。

## 八、Sprint 模块

### 8.1 创建 Sprint

```
POST /api/sprints
```

**请求体：**
```json
{
  "projectId": 1,
  "name": "Sprint 1",
  "goal": "完成用户模块",
  "startDate": "2024-01-15",
  "endDate": "2024-01-28"
}
```

初始状态为 `PLANNING`。

### 8.2 获取 Sprint

```
GET /api/sprints/{id}
```

### 8.3 项目的 Sprint 列表

```
GET /api/sprints/project/{projectId}
```

**响应：**
```json
{
  "code": 200,
  "data": [
    {
      "id": 1,
      "name": "Sprint 1",
      "goal": "完成用户模块",
      "startDate": "2024-01-15",
      "endDate": "2024-01-28",
      "status": "ACTIVE",
      "isActive": 1,
      "totalIssues": 8,
      "completedIssues": 4,
      "projectName": "Mimo开发"
    }
  ]
}
```

### 8.4 启动 Sprint

```
PUT /api/sprints/{id}/start
```

状态从 `PLANNING` → `ACTIVE`。自动停用同项目其他活跃 Sprint，并生成首日燃尽快照。

### 8.5 完成 Sprint

```
PUT /api/sprints/{id}/complete
```

状态从 `ACTIVE` → `COMPLETED`。

## 十、报告模块

### 10.1 生成报告

```
POST /api/reports/generate
```

**请求体：**
```json
{
  "projectId": 1,
  "type": "DAILY | WEEKLY",
  "reportDate": "2024-01-20"
}
```

自动统计已完成任务生成报告内容，初始状态为 `DRAFT`。

### 10.2 报告列表

```
GET /api/reports?type=DAILY&projectId=1
```

参数均可选。

### 10.3 获取报告

```
GET /api/reports/{id}
```

### 10.4 更新报告

```
PUT /api/reports
```

**请求体：**
```json
{
  "id": 1,
  "content": "markdown 格式内容"
}
```

仅 `DRAFT` 状态的报告可编辑。

### 10.5 提交报告

```
PUT /api/reports/{id}/submit
```

状态从 `DRAFT` → `SUBMITTED`。提交后不可再编辑。

## 十一、附件模块

### 11.1 上传附件

```
POST /api/attachments/upload
```

**表单格式（multipart/form-data）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| issueId | number | 任务 ID |
| file | file | 文件（最大 10MB） |

### 11.2 任务附件列表

```
GET /api/attachments/issue/{issueId}
```

**响应：**
```json
{
  "code": 200,
  "data": [
    {
      "id": 1,
      "fileName": "screenshot.png",
      "fileSize": 204800,
      "uploaderName": "admin",
      "createdAt": "2024-01-20 14:00:00"
    }
  ]
}
```

### 11.3 下载附件

```
GET /api/attachments/{id}/download
```

返回文件流，浏览器自动下载。

### 11.4 删除附件

```
DELETE /api/attachments/{id}
```

| 值 | 级别 |

| 值 | 说明 |
|----|------|

| 值 | 说明 |
